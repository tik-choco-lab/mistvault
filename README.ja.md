# mistvault

TypeScript アプリ向けの分散保管庫ライブラリーです。ブラウザー内で暗号化し、mistl の `tc-escrow v1` プロトコルで保存します。コアに実行時依存はなく、設定 UI は任意で Preact 10 を利用できます。

[English / API 一覧](README.md) · [中文](README.zh.md)

## 導入

```sh
npm install github:tik-choco-lab/mistvault
```

Git 依存として導入すると `prepare` がビルドします。`dist/` は Git 管理対象外です。開発時は `npm install`、`npm run build`、`npm test` を実行してください。

```ts
import { createVault, createMistVaultTransport } from '@tik-choco/mistvault'

const vault = createVault({
  adapter,
  transport: () => createMistVaultTransport({ createNode, storageAdd, storageGet }),
})
```

`adapter` には固定の `app` ID、バージョン付き `schema` と、アプリのストアを操作する `snapshot`、`parse`、`merge`、`apply`、`subscribe` を実装します。`parse` はリモート JSON を検証し、不正なら例外を投げます。`merge` は両側の新しいレコードと削除情報を保持する、決定的で冪等な関数にしてください。同一更新時刻の衝突にも一定の規則を使います。削除情報はオフライン端末が戻れる期間、例えば 90 日間保持します。`apply` は結果を保存して画面を更新します。呼び出しが同期的に発生させた通知だけを抑制し、非同期処理中の編集は未保存として保持します。各レコードの書き込み直前にスナップショット時のリビジョンと比較し、変化したレコードはスキップしてください。比較と書き込みは同一の同期処理または IndexedDB の readwrite トランザクションで行い、ローカルの削除情報を保持します。コントローラーも適用前の編集を検知してマージを再試行し、適用後の状態を確認します。

API キー、サービス設定、トークン、ID の秘密鍵、保管庫コード、再生成可能なキャッシュはスナップショットに含めないでください。

`createNode` は呼び出しごとに、アプリの既存の共有ノードスコープから新しい専用ハンドルを返す関数です。トランスポートはルームごとに一つのハンドルを作成し、`leaveRoom(room)` で解放します。ルーム引数のないイベントはそのハンドルのルームに属し、他ルームが明示されたイベントは無視します。ノードは有効化後に初めて作成されます。`storageAdd` / `storageGet` に既存のストレージ関数を渡します。送信は信頼性付き配信 `0`、制御メッセージは最大 16 KiB、参加前キューは最大 64 件です。既定のイベント番号は `raw: 0`、`peerConnected: 2`、`peerDisconnected: 3` で、`events` で変更できます。同じ `storageGet` 関数を使うハンドル間では CID ごとの同時取得を共有します。

## 設定パネル

```tsx
import { VaultPanel } from '@tik-choco/mistvault/preact'
import '@tik-choco/mistvault/ui.css'

<VaultPanel controller={vault} locale="ja" appName="ノート" />
```

有効化とコード読み込み、アプリ別の切り替え、状態、保存・復元、ルーム設定、コードの表示・コピー、別端末用リンク、確認付きコード読み込み、添付件数を表示します。独自 UI には `useVault(vault)` を使えます。英語、日本語、簡体字、繁体字に対応し、省略時はブラウザーの言語を使います。未対応言語は英語になります。

パネルの表示前に端末用リンクを読み取った場合は、非公開に保持したコードを `pendingCode` に渡せます。確認後またはキャンセル後に `onPendingHandled(result)` が `"imported"` または `"cancelled"` を受け取るので、その中で `pendingCode` をクリアしてください。不正なコードを閉じた場合も `"cancelled"` になります。無効時にコードを読み込むと、確認後に自動モードで有効になります。

配色は `--mv-fg`、`--mv-muted`、`--mv-border`、`--mv-accent`、`--mv-bg` で調整できます。狭い画面で折り返し、システムのライト・ダーク設定に従います。

## コードとルーム

初期状態は無効です。有効にすると 128 ビットのランダムな保管庫コードを生成し、自動モードになります。同一オリジンのアプリは `tc-vault:settings-v1` を共有し、他のタブの変更にも追従します。アプリ別の進行状況は `tc-vault:app:<app>:v1` に保存します。別のコードに切り替えると、各アプリのシーケンス、ハッシュ、添付情報をリセットします。アプリのローカルデータと有効・無効の設定は残ります。

自動モードのルームは `deriveAutoRoom('tc-vault', code)` で決まり、すべてのアプリで一つを共有します。表示されたルームを mistl の「ストレージ → 分散保管庫」に追加するか、次を実行します。

```sh
mistl escrow rooms add <room>
```

コードを知る人は保管庫を読み書きできます。コードは秘密として保管してください。端末用リンクではコードを URL フラグメントに入れます。パネルはマウント時にフラグメントを削除し、明示的な確認後に読み込みます。設定画面を遅れて表示するアプリでは、起動時に `consumeVaultLink()` を呼び、戻り値を非公開の状態に保持して `pendingCode` に渡すか、独自の確認操作後に `importCode` へ渡してください。リンクの消費だけでは読み込みません。

## 操作と同期

進行状況と添付キャッシュはコードと実際のルームの組み合わせに属し、どちらかが変わるとリセットします。参加失敗やプロバイダー消失時は、画面が表示中なら 5 秒から最大 60 秒まで待ち時間を倍増して再参加します。online イベントでも再試行します。他のタブの編集も共有の未保存フラグと編集世代に記録し、書き込みタブは保存前と定期確認で読み取ります。保存後は、そのスナップショット以降に編集がない場合だけ未保存フラグを解除します。

- `getView()` / `subscribe(cb)`：状態、エラー、時刻、シーケンス、添付件数を取得・購読します。
- `enable()` / `disable()`：全体を自動モードまたは無効にします。
- `setAppEnabled(on)`：このアプリの参加だけを切り替えます。
- `configure(mode, room?)`：`auto` / `custom` / `off` を指定します。不正なルームなら `false` を返します。
- `importCode(code)` / `revealCode()`：確認済みコードへの切り替え、現在のコードの取得です。不正な読み込みは `false` になります。
- `saveNow()` / `restoreNow()`：未保存データを送るか、リモートを取得してマージします。
- `dispose()`：タイマー、購読、ロック、通信を終了します。

無効時はノードを作成しません。起動時は最大 20 秒プロバイダーを探し、見つからなくても待ち受けを続けます。最初の復元試行が成功するまでは保存しません。変更から 8 秒間静かになるか、最初の変更から最大 60 秒で保存します。画面が非表示になると可能な範囲で保存します。競合時は取得・マージして最大 3 回保存を試し、失敗は状態に表示して 60 秒後や次の変更で再試行します。

`navigator.locks` があればアプリごとに一つのタブが書き込みます。他のタブは保存通知と、表示中の 60 秒間隔の確認で復元します。ロックの引き継ぎ時も先に復元します。ロック非対応環境ではプロトコルの比較交換とマージで競合を処理します。終了時の保存は完了を保証できないため、アプリ自体のローカル永続化は必要です。localStorage が使用できなくても実行中の設定は保持しますが、再起動後の保持やタブ間共有はできません。

## 添付ファイル

`adapter.parts` に `list(state)`、`read(id)`、`has(id)`、`write(id, bytes)`、任意の `maxBytes` を指定します。ID は `[A-Za-z0-9_.:-]{1,128}`、サイズは非圧縮の実サイズです。`f:` と SHA-256 のような内容に基づく ID を推奨します。

アプリの PBKDF2 マスターを再利用して、添付ごとに別の暗号化・署名・スロット鍵を派生します。新規・変更済み添付を先にアップロードし、続いて本体を保存します。復元後に不足する添付を最大 2 件ずつ取得します。既定上限は 32 MiB − 64 KiB です。大きすぎるファイル、ローカルにないファイル、プロバイダーの容量制限で保存できないファイルは省略として記録し、本体の保存を続けます。省略情報は端末のアプリごとに保持します。

保存・復元時にはローカルに添付があってもプロバイダーのヘッドを確認し、不在・削除済みならアップロード済みキャッシュを無効化してローカルのバイト列から修復します。本体の保存確認後にも再確認します。取得できない添付は保留のまま後続の復元や表示中の定期確認で再試行し、代替のバイト列は書き込みません。

確認済み・観測済みの現在の本体で、少なくとも24時間参照されていない添付だけが削除候補になります。添付ごとの `unreferencedSince` を保存し、参照が戻るとリセットします。`partGcGraceMs` に0以上のミリ秒数を指定して猶予期間を変更できます。猶予と修復は遅延削除の競合を軽減しますが、完全に防ぐにはプロバイダー側の参照カウントが必要です。削除直前には添付の世代と、本体の確認済みヘッドが今も最新であることを確認します。本体が変わっていれば削除を延期します。送信前にアップロード済みキャッシュから除外し、削除再試行用の記録を別に保持するため、削除確認を受信できなくても再導入できます。プロバイダーの `delete` 機能が必要です。`delete-continue` 対応なら削除済みヘッドの次のシーケンスで再作成できます。

## コアとライセンス

`EscrowClient.join(true)` はプロバイダー不在時に参加を取得し直します。`onProvider` は切断時にも通知するため、`providers` で現在の可用性を確認してください。保持していた保存先情報が失われたヘッドの削除は、全コピーの削除を保証できないため既存の `error` 結果と `transport` コードを返します。通信形式とアダプターの必須 API は変わりません。

`EscrowClient`、`deriveEscrowKeys`、`derivePartKeys`、`deriveAutoRoom`、ヘッドの署名・検証、プロトコルの解析、制限値も公開しています。添付鍵には `fetchLatestWithKeys` / `saveWithKeys` / `deleteWithKeys` を使えます。完全な API 一覧と型は [英語 README](README.md#portable-api) を参照してください。

Web Crypto の Ed25519、AES-GCM、PBKDF2、HKDF が必要です。利用可能ならブラウザーの圧縮ストリームを使います。保存確認は受信プロバイダーへの永続化を示し、複製は mistl の設定に従います。重要なデータには独立したバックアップも保管してください。
